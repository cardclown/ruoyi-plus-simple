# MinIO 动态访问地址配置

## 配置入口

使用现有的“系统管理 → OSS 配置”维护 MinIO，不新增重复的 IP 配置项。

同机部署且局域网 IP 由 DHCP 分配时，默认 MinIO 配置应为：

| 配置项 | 值 | 作用 |
| --- | --- | --- |
| `endpoint` | `127.0.0.1:9000` | 后端上传、下载和删除使用的稳定内部地址。 |
| `domain` | 留空 | 公共桶 URL 根据当前 HTTP 请求 Host 动态生成。 |
| `isHttps` | `N` | 与本机 MinIO 实际协议保持一致。 |
| `accessPolicy` | `1` | 公共桶，允许浏览器直接读取图片和视频。 |

## 地址生成规则

- 数据库 `sys_oss.url` 只保存 `http://127.0.0.1:9000/...` 内部地址，不保存动态局域网 IP。
- 浏览器请求接口时，后端把公共桶 URL 的主机替换为当前请求 Host，并保留 MinIO 的 `9000` 端口、桶名和对象路径。
- 经过可信代理时优先读取 `Forwarded`、`X-Forwarded-Host`；开发代理把 Host 改成 localhost 时使用浏览器 `Origin` 或 `Referer`。
- 后台清理和删除任务没有 HTTP 请求，不转换 URL，因此始终能使用稳定内部地址操作 MinIO。
- `domain` 一旦填写，说明管理员提供了固定域名，该域名优先，动态 Host 自动关闭。

例如客户端通过 `http://10.50.3.55:8080` 访问接口，数据库中的：

```text
http://127.0.0.1:9000/ruoyi/2026/08/example.mp4
```

响应时会转换为：

```text
http://10.50.3.55:9000/ruoyi/2026/08/example.mp4
```

IP 后续变化时无需修改数据库。

## 固定域名和私有桶

- 生产环境有固定文件域名时，在 `domain` 中填写域名，后端不会动态替换。
- 私有桶的签名包含 Host，不能在签名后替换地址；私有桶必须配置客户端可访问的稳定 `domain`。
- 通过后台 OSS 配置页面修改会同步刷新缓存；如果直接修改数据库，需要重启服务重新初始化 OSS 缓存。
