# 用户名称格式校验设计

## 背景

用户管理的新增用户表单目前只限制用户名称必填和长度，后端 `SysUserBo` 也未限制字符范围，因此中文和符号可以作为登录账号。业务要求将用户名称限定为英文大小写字母和数字，同时允许纯数字账号，以支持使用手机号作为账号。

## 目标

- 用户名称长度保持为 2～20 个字符。
- 用户名称只允许 `A-Z`、`a-z` 和 `0-9`。
- 允许纯字母、字母数字组合和纯数字账号。
- 前端提供即时、明确的错误提示。
- 后端执行相同的强制校验，防止绕过前端直接提交非法账号。

统一规则为：

```regex
^[A-Za-z0-9]{2,20}$
```

## 设计

### 后端校验

在 `SysUserBo.userName` 上保留必填与 XSS 校验，将长度上限从 30 统一为 20，并增加英文大小写字母和数字的格式校验。新增和编辑接口继续使用现有 Bean Validation 入口，因此非法账号会在业务写入前被拒绝。

后端是最终校验来源。即使调用方绕过管理页面，中文、空格、下划线、短横线和其他符号也不能写入。

### 前端校验

在公共校验工具中增加可复用的用户名称规则，并在用户管理新增表单的 `userName` 规则中使用它。前端长度校验仍提供长度错误提示，字符规则提供“用户名称只能包含英文字母和数字”的格式错误提示。

### 数据兼容性

实施前数据库中剩余的 5 个有效用户名称均符合新规则，无需迁移。用户名称在管理页面中只允许新增时输入，现有合法用户的编辑流程不受影响。

## 验收示例

以下用户名称应通过：

- `ZhangSan`
- `zhangsan01`
- `13800138000`
- `ABC123`

以下用户名称应被拒绝：

- `张三`
- `abc_123`
- `abc-123`
- `abc 123`
- `a`
- 超过 20 个字符的字母数字组合

## 测试与验证

- 后端 Bean Validation 测试覆盖大小写字母、字母数字、纯数字、中文、符号和长度边界。
- 前端规则测试覆盖合法与非法字符组合。
- 运行后端目标模块测试，确认新增校验通过且无回归。
- 运行前端测试、类型检查或生产构建与 ESLint，确认规则可以被页面正常引用。

## 非目标

- 不判断字母组合是否为语言学意义上的汉语拼音。
- 不修改登录接口对历史账号的读取行为。
- 不修改用户昵称；用户昵称仍可使用中文。
- 不扩大到注册、租户初始化或用户导入入口。
