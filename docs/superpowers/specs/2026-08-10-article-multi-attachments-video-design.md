# 文章多附件与视频上传设计

## 目标

为文章管理增加两个彼此独立的多文件字段：普通附件和视频。封面继续沿用现有单值 `coverOssId`；普通附件与视频通过新的文章附件关联表保存。文件仍由现有 OSS 文件模块统一上传、查询、预览和下载，文章数据不保存永久 URL。

本次同时解决当前 OSS 上传实现会把整个文件读入 JVM 堆的问题，使最大 2 GiB 的视频能够经后端流式上传到 MinIO，并补充上传中断、临时文件、未完成分片和未绑定文件的清理机制。

## 范围

- 一篇文章最多绑定 10 个普通附件和 5 个视频。
- 单个视频最大 2 GiB。
- 视频格式支持 MP4、AVI、MOV、WebM、MKV、WMV、FLV。
- 文章新增、修改、详情、列表、逻辑删除和物理删除均处理附件关系。
- 文章列表返回正文 `content`，但不要求列表页面直接展示正文。
- 文件 URL 继续通过文件模块动态解析，不在文章表或附件关联表保存 URL。
- 浏览器到后端仍是一次普通 multipart 请求；本期不实现浏览器断点续传，也不引入 FFmpeg 转码。

## 数据模型

### 文章表

`content_article` 保留现有 `cover_oss_id`，不增加单值 `video_oss_id`。多附件和多视频均保存在关联表中，避免主表保存逗号分隔 ID 或同时维护单值与关联数据。

### 文章附件关联表

新增 `content_article_attachment`：

| 字段 | PostgreSQL 类型 | 可空 | 说明 |
|---|---|---:|---|
| `article_attachment_id` | `bigint` | 否 | 雪花 ID 主键 |
| `article_id` | `bigint` | 否 | 文章 ID |
| `oss_id` | `bigint` | 否 | `sys_oss.oss_id` |
| `attachment_type` | `char(1)` | 否 | `0` 普通附件，`1` 视频 |
| `sort_num` | `integer` | 否 | 在对应页面字段中的顺序，从 0 开始 |
| `create_by` | `bigint` | 是 | 创建人 |
| `create_time` | `timestamp` | 是 | 创建时间 |

约束和索引：

- `article_attachment_id` 为主键。
- `oss_id` 建立唯一约束，文章业务中的一个 OSS 文件只能绑定一次。
- `(article_id, attachment_type, sort_num)` 建立组合索引，用于批量回显和稳定排序。
- 关联表不保存 URL、租户编号或逻辑删除标志。租户权限通过文章和 `sys_oss` 两端校验，配置方式与现有文章标签关联表保持一致。
- 不建立数据库外键，关联清理由文章服务显式完成，保持当前项目的表结构风格。

## 请求与响应模型

文章新增、修改、详情和列表统一使用以下附件字段：

```json
{
  "coverOssId": 100,
  "attachmentOssIds": [101, 102],
  "videoOssIds": [201, 202]
}
```

- `attachmentOssIds` 和 `videoOssIds` 均允许为空数组。
- 后端去重并保留首次出现的顺序。
- 普通附件最多 10 个，视频最多 5 个。
- 同一个 OSS ID 不得同时出现在两个列表中，也不得绑定到另一篇文章。
- 编辑文章时允许继续使用本文章已经绑定的 OSS ID。
- `ContentArticleBo` 和 `ContentArticleVo` 使用 `List<Long>`，不使用逗号分隔字符串。

## 上传设计

### 接口语义

继续复用文件模块的上传能力，在 multipart 上传请求中增加可选业务类型 `bizType`：

- `article_attachment`：文章普通附件。
- `article_video`：文章视频。

响应保持现有结构和语义，返回 `ossId`、`fileName` 和 `url`。其中 URL 只用于上传完成后的当次预览，文章不会保存该 URL。

即使客户端绕过 `bizType` 上传，文章保存时仍会重新校验文件信息，因此上传接口不是最终业务校验边界。

### 视频校验

视频上传和文章绑定均执行以下校验：

- 文件不能为空。
- 文件大小不得超过 `2 * 1024 * 1024 * 1024` 字节。
- 扩展名允许 `mp4`、`avi`、`mov`、`webm`、`mkv`、`wmv`、`flv`。
- 同时检查扩展名和 MIME 类型；不只相信客户端文件名或 `Content-Type`。
- 普通附件列表不得通过伪造类型绕过视频限制，命中视频格式的文件必须按视频规则校验。

普通附件继续遵循文件模块现有的通用文件限制，本次只新增每篇文章最多 10 个的绑定限制。

### 流式上传

当前实现中的 `MultipartFile.getBytes()` 和 `IoUtil.readBytes(inputStream)` 会让大文件完整进入 JVM 堆，必须移除。新的上传链路为：

1. 从 `MultipartFile` 获取输入流和已知长度。
2. 使用异步请求体把输入流交给 S3 异步客户端。
3. 为 S3 异步客户端启用自动 multipart，建议最小分片约 32 MiB、上传并发数 3 至 4。
4. MinIO 上传成功后写入 `sys_oss`。
5. 只有 MinIO 对象和 `sys_oss` 记录都成功时才返回上传成功。
6. 如果 MinIO 成功而 `sys_oss` 写入失败，立即删除刚上传的 MinIO 对象。

浏览器到后端仍是单个 HTTP 上传请求，所以 SDK 分片只发生在“后端到 MinIO”这一段。浏览器连接中断后，前端需要重新上传整个文件。

## 临时文件和未绑定文件清理

### 请求临时文件

- 上传成功、校验失败、MinIO 异常和客户端连接中断时均关闭输入流，并由请求生命周期立即清理对应的 servlet multipart 临时文件。
- multipart 临时目录使用独立、明确的配置路径，不能与业务文件目录混用。
- 服务运行期间每小时扫描一次该目录。
- 只删除最后修改时间超过 24 小时、且当前未处于活跃写入状态的临时文件。
- 扫描逻辑不得只依赖“下次启动”，也不得用 10 分钟之类可能误伤长时间上传的阈值。

### MinIO 未完成分片

- 应用在失败路径主动取消 multipart 上传。
- MinIO bucket 配置未完成 multipart 的生命周期清理，作为进程崩溃和网络异常后的兜底。
- 上传经过后端，不需要为该功能增加 MinIO CORS 配置。

### 已上传但未保存文章的文件

现有 `SysOssExt` 已包含 `bizType`、`refId`、`refType` 和 `isTemp`，本设计直接复用：

1. 文章附件或视频上传成功后写入 `isTemp=true` 和对应 `bizType`。
2. 文章新增或修改成功后，写入文章 ID，并把 `isTemp` 改为 `false`。
3. 每小时清理创建时间超过 24 小时且仍未绑定的文章临时 OSS 文件。
4. 清理同时删除 MinIO 对象和 `sys_oss` 记录。

该规则只清理明确标记为文章临时上传的文件，不扫描或猜测其他业务模块的 OSS 文件。

## 文章保存流程

### 新增

1. 校验文章字段、分类和标签。
2. 对两个附件列表去重，检查数量和交叉重复。
3. 批量读取全部 OSS 元数据，校验文件存在、当前租户可访问、尚未绑定其他文章、类型和大小有效。
4. 新增文章和标签关系。
5. 按请求顺序批量新增附件关系。
6. 将对应 `sys_oss` 批量标记为已绑定文章。

关系表写入使用 MyBatis-Plus 批量能力，不为新增流程编写手写 SQL。

### 修改

1. 先读取并校验当前文章及其附件关系。
2. 对新列表执行与新增一致的校验；本文章原有 OSS ID 不视为重复绑定。
3. 比较新旧集合：新增关系、删除移除关系、更新顺序变化。
4. 文章及关系保存成功后，通过文件模块删除已移除且不再属于文章的 OSS 对象和 `sys_oss` 记录。

仅调整顺序时不重新上传或删除文件。附件删除失败时修改操作返回失败并记录明确错误，不能静默留下无主文件。

## 查询设计

### 详情

文章详情查询文章主体后，按 `article_id` 查询附件关系，按 `attachment_type` 和 `sort_num` 组装 `attachmentOssIds`、`videoOssIds`。

### 列表

文章分页和普通列表继续使用现有 MyBatis-Plus 查询包装器：

- 显式把 `content` 加入列表查询字段，使列表响应包含正文。
- 分页得到文章 ID 集合后，一次批量查询整页附件关系。
- 在内存中按文章 ID 和附件类型分组并写回 VO，避免逐篇查询造成 N+1。
- 不新增文章列表 XML 查询 SQL。

前端拿到 ID 列表后，合并本页需要回显的 OSS ID，一次调用文件模块 `listByIds` 获取当前有效 URL。私有 bucket 获得新的临时 URL，公开 bucket 获得当前直接访问地址；文章接口不关心具体 URL 策略。

## 预览和下载

- 上传完成后可直接使用上传响应中的 URL 做当次预览。
- 再次进入详情、编辑或列表页面时，通过 `listByIds` 解析当前 URL。
- 下载继续使用现有 `/resource/oss/download/{ossId}`，由后端按文件模块权限处理。
- MP4、WebM 等浏览器和编码均支持的文件使用 `<video controls preload="metadata">` 预览。
- AVI、WMV、FLV、部分 MOV/MKV 等无法由浏览器原生播放时，页面显示“当前格式不支持在线预览”并提供下载。
- 本期不做永久 URL、不把 URL写入文章数据，也不增加 FFmpeg 转码。

## 删除设计

### 逻辑删除

文章普通删除只设置文章逻辑删除标志，保留标签关系、附件关系、封面和所有文件。文章恢复后附件仍可继续使用。

### 物理删除

仅已逻辑删除且通过租户与数据权限校验的文章可以物理删除。处理顺序为：

1. 批量读取文章的封面 ID 和全部附件关系。
2. 对 OSS ID 去重。
3. 通过文件模块删除 MinIO 对象及 `sys_oss` 记录。
4. 删除文章附件关系和标签关系。
5. 物理删除文章记录。

文章业务不支持附件共享，因此不增加引用计数或“被其他文章引用则跳过”的分支。附件删除操作需要可重试、可识别对象已不存在的幂等结果。任一附件清理失败时，物理删除返回失败，文章保留在回收站供再次处理。

## SQL 与模块边界

- SQL 只负责创建 `content_article_attachment`、注释、唯一约束和组合索引。
- 附件关系的查询、新增、修改和删除全部使用 MyBatis-Plus 包装器及批量方法。
- 现有用于绕过逻辑删除过滤的文章物理删除 XML SQL继续保留。
- 文件模块负责上传、URL解析、下载、OSS元数据、绑定状态和物理文件删除。
- 文章模块负责文章与 OSS ID 的业务关系、数量、类型、顺序和删除时机。
- 通用 `OssService` 接口扩展批量元数据、绑定和删除能力，文章模块不直接依赖系统模块的 Mapper 或实体。

## 配置要求

- Spring multipart 单文件和单请求上限需要覆盖 2 GiB 视频及 multipart 额外开销。
- 如果部署链路包含 Nginx或其他反向代理，其请求体上限、读取超时和发送超时也必须允许数小时的慢速上传。
- MinIO 无需因 2 GiB 对象调整常规对象大小限制，但需要配置未完成 multipart 生命周期清理。
- 当前单节点 MinIO 可以承载该功能，但不提供节点级冗余；生产数据可靠性仍需依靠备份或多节点部署。

## 错误处理

- 格式不支持：返回明确的视频格式错误。
- 超过 2 GiB：在进入 MinIO 前拒绝。
- OSS ID 不存在或不属于当前租户：拒绝文章保存。
- OSS ID 已绑定其他文章：拒绝文章保存。
- 数量超过限制或两个列表存在交叉重复：拒绝文章保存。
- MinIO 上传成功但数据库保存失败：补偿删除 MinIO 对象。
- 客户端断开或上传失败：关闭流、清理本地临时文件并取消未完成 multipart。
- 删除失败：返回失败，不把未完成的物理删除伪装成成功。

## 验证范围

### 文章服务测试

- 普通附件 0、1、10、11 个的边界。
- 视频 0、1、5、6 个的边界。
- 重复 ID、跨列表重复 ID和已绑定其他文章的校验。
- OSS 文件不存在、跨租户、视频类型不符和超过 2 GiB 的校验。
- 新增、修改、排序、移除附件和批量回显。
- 列表响应包含 `content`、`attachmentOssIds` 和 `videoOssIds`。
- 列表附件查询为一次批量查询，不产生 N+1。
- 逻辑删除保留文件，物理删除清理文件和关系。

### 文件服务测试

- 上传实现不调用 `MultipartFile.getBytes()` 或把完整输入流读入字节数组。
- 小文件和触发 multipart 的大文件都能正确上传。
- MinIO 成功、`sys_oss` 失败时执行补偿删除。
- 上传异常和连接中断时关闭流并清理本地临时文件。
- 临时清理任务不删除 24 小时内文件或活跃上传，只删除过期未绑定文章文件。
- 私有和公开 bucket 均继续通过 `listByIds` 返回符合当前配置的 URL。

### 前端验证

- 页面分别展示普通附件和视频两个多文件控件。
- 普通附件最多 10 个，视频最多 5 个。
- 支持格式能预览；浏览器不支持的格式能正常下载。
- 新增、编辑、删除和重新进入页面时顺序及回显一致。
- 大文件上传展示进度，上传请求使用独立的长超时配置，不影响普通 API。

## 验收标准

- 2 GiB 以内允许格式的视频可通过后端稳定上传到 MinIO，JVM 堆占用不随完整文件大小增长。
- 文章可保存最多 10 个普通附件和 5 个视频，并按请求顺序返回。
- 文章列表返回正文和两个附件 ID列表，不保存或返回固化的永久 URL字段。
- 所有页面回显均沿用文件模块 `listByIds` 解析当前有效 URL。
- 正常完成、失败、中断和过期未绑定场景都有明确清理路径。
- 逻辑删除不删附件，物理删除清理文章相关封面、普通附件和视频。
- 新增的业务查询和关系维护使用 MyBatis-Plus，不引入新的手写列表查询 SQL。
