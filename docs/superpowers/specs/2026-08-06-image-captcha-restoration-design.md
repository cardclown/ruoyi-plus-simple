# 图片验证码最小恢复设计

## 背景

当前后端基于 RuoYi-Vue-Plus 5.6.2 精简而来。精简提交删除了完整验证码链路，因此前端访问 `GET /dev-api/auth/code` 时，Vite 虽能正确代理到 `http://localhost:8080/auth/code`，后端仍返回“请求地址不存在”。前端与后端的网络连接本身正常。

## 目标

恢复 RuoYi-Vue-Plus 原有的图片验证码能力，使密码登录和用户注册重新校验图片验证码，同时保持短信验证码、邮箱验证码和第三方登录等已精简功能处于删除状态。

## 范围

恢复以下能力：

- `GET /auth/code` 生成图片验证码，返回 `captchaEnabled`、`uuid` 和 Base64 图片。
- 将验证码答案写入 Redis，默认有效期为 2 分钟。
- 密码登录和用户注册读取 `code`、`uuid` 并校验 Redis 中的答案。
- 验证码无论正确或错误，校验后均立即从 Redis 删除，保证一次性使用。
- 恢复验证码开关、类型和长度配置，默认启用数学验证码。
- 保留原有按 IP 限流，每分钟最多生成 10 次。

不恢复以下能力：

- 短信验证码接口。
- 邮箱验证码接口。
- 邮件、短信、社交登录或微信小程序相关依赖。
- 与图片验证码无关的已精简模块。

## 实施方式

采用“原版恢复后再精简”，不重新手写验证码实现：

1. 从精简提交 `8ba8d9516` 的父提交恢复 RuoYi-Vue-Plus 5.X 原版验证码控制器、配置、请求字段、异常、Redis key、校验逻辑和依赖。
2. 先编译并验证原版图片验证码链路，确保恢复内容与当前 5.6.2 基线一致。
3. 再从恢复内容中删除短信验证码、邮箱验证码及其邮件/SMS 依赖，只保留图片验证码。
4. 再次执行完整验证，确认二次精简没有破坏图片验证码。

这种方式优先复用仓库中已经验证过的 5.X 实现，避免人工重写产生行为偏差。

## 组件与改动边界

### 验证码生成

先恢复 5.X 原版验证码配置属性、自动配置、图片渲染类、`CaptchaController` 和相关依赖。原版恢复验证完成后，再从 `CaptchaController` 删除短信和邮箱端点，并移除对应邮件、SMS 依赖；最终控制器只保留图片验证码端点。

验证码配置位于 `application.yml`：默认开启、类型为 `math`、数字长度为 1、字符模式长度为 4。生成后使用 `global:captcha_codes:<uuid>` 作为 Redis key，TTL 为 2 分钟。

### 登录与注册校验

恢复登录请求对象的 `code` 和 `uuid` 字段，以及验证码过期、验证码错误异常和对应国际化消息。

密码登录在查询用户和校验密码之前检查验证码；注册在创建用户之前检查验证码。配置关闭时跳过验证码校验，与原版 5.X 行为一致。

### 前端连接

前端不改业务代码：Axios 继续使用 `/dev-api`，Vite 继续把它代理到 `http://localhost:8080`。现有登录页已经能够显示接口返回的图片，并在登录请求中提交 `code` 与 `uuid`。

## 数据流

1. 登录页请求 `/dev-api/auth/code`。
2. Vite 去掉 `/dev-api` 前缀并代理到后端 `/auth/code`。
3. 后端生成验证码、把答案写入 Redis，并返回图片与 `uuid`。
4. 用户提交用户名、密码、验证码和 `uuid`。
5. 后端从 Redis 读取并立即删除验证码。
6. 验证码匹配后继续密码校验；过期或错误时返回现有 RuoYi 验证码错误响应。

## 错误处理

- Redis 中不存在 key：按验证码过期处理，并记录失败登录日志。
- 用户输入与 Redis 答案不匹配：按验证码错误处理，并记录失败登录日志。
- 验证码关闭：接口返回 `captchaEnabled=false`，登录与注册跳过校验。
- Redis 不可用：沿用当前全局异常处理，不降级为跳过验证码，避免绕过登录保护。

## 验证

- 原版恢复后先执行后端 Maven 编译/测试，确认恢复内容完整。
- 删除短信和邮箱验证码后再次执行 Maven 编译/测试，确认二次精简后的模块依赖仍完整。
- 直连 `http://localhost:8080/auth/code`，确认响应包含图片与 `uuid`。
- 通过 `http://localhost/dev-api/auth/code` 请求，确认前端代理链路返回同样结果。
- 验证错误验证码被拒绝，且同一 `uuid` 不能重复使用。
- 验证正确验证码能够进入后续密码校验。
- 打开登录页，确认图片展示、点击刷新和登录请求均正常。
