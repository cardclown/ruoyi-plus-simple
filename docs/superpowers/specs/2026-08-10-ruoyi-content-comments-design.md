# ruoyi-content 注释补充设计

## 背景

`ruoyi-content` 是本项目新增的文章管理模块，目前类级注释和 Controller 接口说明已覆盖一部分代码，但 Service 接口、Mapper、BO/VO 字段以及若干复杂业务流程的说明不足。维护者需要通过阅读实现细节才能理解请求边界、租户与数据权限、发布状态流转、富文本过滤和删除策略。

本次只补充能够解释公共契约、业务约束和设计原因的注释，不改变任何运行行为。

## 目标

- 让维护者不深入实现即可理解每个公共类和公共方法的职责。
- 明确新增与修改的请求字段边界，以及 ID、审计字段由后台负责的原因。
- 解释文章发布、字典校验、标签保存、富文本清洗、数据权限和删除策略中的非显然规则。
- 与 RuoYi 现有模块的 Javadoc 风格保持一致。

## 范围

覆盖 `ruoyi-modules/ruoyi-content/src/main/java` 下现有 18 个 Java 文件：

- Controller 与 Service 接口、实现；
- 文章实体、标签关联实体、BO、Query、VO；
- Mapper；
- 字典枚举；
- 发布策略、操作上下文、字典适配、删除校验、富文本过滤等 support 类；
- `LongListTypeHandler`。

不修改框架公共模块、测试、SQL、配置和前端代码。

## 注释层级

### 类级注释

每个公共类说明它承担的职责、主要边界和关键依赖。对于安全或数据边界类，说明其存在原因，而不只复述类名。

### 公共方法 Javadoc

Controller、Service 接口、Mapper 和 support 类的公共方法补齐：

- 方法完成的业务动作；
- `@param` 参数含义和重要约束；
- `@return` 返回结果的语义；
- 必要时说明异常条件、租户或数据权限边界。

Service 实现的接口方法可保留与接口一致的简洁说明，但重点业务原因放在实现中的关键流程附近，避免大段重复。

### 字段注释

实体、BO、Query、VO 和字典枚举字段说明数据含义。重点标明：

- `articleId` 仅修改请求接收，新增时由 MyBatis-Plus 雪花策略生成；
- 创建人、创建部门、创建时间、更新人和更新时间由后台审计机制填充，不属于请求字段；
- `tagIds` 的数量、去重和字典编码语义；
- 发布状态、发布人和发布时间的关系；
- OSS 封面 ID、逻辑删除标记和导出字段含义。

### 行内注释

只在代码无法自行表达“为什么”的位置添加，包括：

- JsonView 与校验分组共同限制新增、修改的请求字段；
- 发布状态切换时保留或重置发布信息；
- 富文本过滤中为兼容 Quill `data-list` 所做的临时属性转换；
- HTML 样式白名单和危险值阻断；
- 逻辑删除与物理删除的前置校验；
- 标签关系由后台补充操作人和操作时间；
- Mapper 的数据权限注解保证单条、列表、更新和删除使用同一权限边界。

不为普通赋值、简单条件判断、循环、getter/setter 添加复述式注释。

## 行为边界

本次变更必须满足：

- 只修改注释和空白排版；
- 不修改 Java 注解、方法签名、字段、常量、SQL 或依赖；
- 不改变 API 请求和响应模型；
- 不改变新增 ID、审计字段、分页、数据权限、发布、标签、OSS 和删除逻辑；
- 不暂存或提交工作区中其他业务改动及 `script/sql/update` 下已有删除。

## 验证

- 用 Git 差异确认生产文件只发生注释或必要的空白排版变化；
- 运行 `git diff --check`；
- 运行 `mvn -pl ruoyi-modules/ruoyi-content -am -DskipTests=false test`；
- 确认 `ruoyi-content` 全部测试通过；
- 确认 `script/sql/update` 下仍恰好保留原有 40 个暂存删除，且注释提交不包含它们。
